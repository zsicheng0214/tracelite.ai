Abstract

Prevailing benchmarks for software and terminal agents evaluate models almost exclusively inside uniform “greenhouse” containers configured with permissive system defaults, confounding algorithmic coding skill with real-world environment adaptability. We introduce TwinEnv-Bench, a controlled micro-scale benchmark of 117 scripting, systems, and data-engineering tasks that pairs identical user instructions and codebases across a standard baseline container and a target sandbox shifted along a single verified system property.

Spanning a five-layer operating-system taxonomy enforced by mechanical solvability contracts and leak-proof host-isolated grading, TwinEnv-Bench contrasts interactive-exposed shifts, where discrepancies trigger immediate errors during sample runs, against deployment-latent shifts, where sample runs pass silently while production constraints reside in scheduled jobs, mount boundaries, process privileges, or resource quotas.

Evaluating nine frontier models across non-refusal executed runs reveals that near-ceiling baseline competence collapses to 26.8%–67.1% single-run solve rates and 14.5%–59.5% multi-run reliability under single-variable shifts. Models that lead exposed shifts via runtime debugging and upfront shallow checking drop sharply and invert rankings under the silent constraints and production-layer shifts of the latent regime, where upfront multi-step reconnaissance is associated with a nearly sixfold higher solve rate than unprobed runs.

Controlled system-prompt interventions further confirm that explicit pre-flight reconnaissance causally lifts latent solve rates by nearly 30 percentage points and doubles multi-run reliability, yet a 43.6 percentage-point cross-model probe-to-action gap persists across the four tested models even under near-saturated probing—indicating that checklist guidance resolves reconnaissance blindness without equalizing underlying system-level reasoning from observed host state to boundary-safe code.

Counterfactual twin-cell architecture & admission contracts

Every failure isolates a single probe-verified system property on a task whose functional logic is demonstrably solvable.

01

Single-variable sandbox audit

55 reusable sandbox configurations (1 base + 54 variants) are audited under the agent’s exact UID and login shell to verify active target enforcement with zero collateral drift on unrelated properties.

02

Six-run solvability contract

Every task passes six deterministic checks across Base and Target: the unmodified workspace fails both (0, 0), the greenhouse-naive solution passes Base and fails Target (1, 0), and a portable reference solution passes both (1, 1).

03

Silent in sample, discoverable on host

Across all 58 deployment-latent tasks, sample inputs pass without error in the interactive shell, yet every active cron file, mount option, UID/capability mask, or kernel quota is readable via standard inspection commands from step 0.

Host-isolated execution & evaluation protocol

Zero-dependency host dispatch, post-termination grading injection, and parallel refusal-as-zero sensitivity accounting.

01

Leak-proof post-run grading

API credentials, reference solutions, and held-out judge feeds (mean 1,712.9 lines) stay strictly on the host across four runtime profiles, injected only after agent termination; all 1,709 package files are SHA-256 verified.

Compound pressure subset

Standard and scheduled tasks allocate up to 32,768 output tokens per turn, whereas the 19 host-isolated tasks pair silent UID, umask, FIFO, and rlimit boundaries with a tightened 6,000-token per-turn output cap and natural-turn termination.

Scope & limitations

TwinEnv-Bench is designed as a controlled micro-scale POSIX scripting, systems, and data-engineering benchmark (median 22-line reference solution) to guarantee single-variable causal purity and self-contained Docker reproducibility on standard Linux hosts. It does not claim to measure full-scale multi-thousand-line repository refactoring, native macOS or Windows desktop semantics, or multi-node distributed cluster failures.

Every task shifts a single verified mechanism Δdi rather than compositional multi-variable shifts, and E5 State currently comprises two tasks (including single-task case E5.2), so group-level bottleneck claims focus on multi-task groups E4.5 and E1.1. Across exposure regimes, Δregime reflects both silent observability and its natural OS-layer distribution, while the 19-task host-isolated subset represents a compound stress test combining silent boundaries with a 6,000-token per-turn output cap.

Finally, unguided test-time resampling findings are scoped to a small K = 3 budget under a unified single-agent tool harness, and our causal intervention evaluates task-agnostic prompt checklists rather than environment-aware reinforcement-learning post-training, for which the residual 43.6 percentage-point cross-model conversion spread provides motivation.
