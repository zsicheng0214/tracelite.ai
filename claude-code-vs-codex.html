Claude Code vs Codex: What Changes When You Keep the Model Fixed?

With Opus 5 in both harnesses, Claude Code passed 51 of 95 TraceTrial-Bench tasks and Codex passed 29. Only 7 and 2 runs, respectively, also passed every harness check.

A trace example: dispatch acceptance versus completion

In one matched Opus 5 case, the task asked a parent agent to delegate a release audit and yield once for the native completion or non-completion signal. Claude Code recorded the dispatch, received the child’s completion payload, and wrote a completed report. Codex also recorded a dispatch, but the child replied that it had no task details and the parent recorded the audit as pending.

The trace shows why an evaluation should check the result delivered to the parent, not just whether the dispatch call was accepted. This example does not explain the aggregate score gap or establish how often the same behavior recurs.

How to use these results

Start with the metric that matches your workload, then inspect the associated traces. If you rely on async delegation, check that the parent receives the child’s actual result. For a reliability estimate, rerun the same setup rather than treating this single retained run per cell as a stability estimate.

These are results for the published v1 configurations, not a ranking of current product versions. Task revisions, runtime settings, recovery conditions, and judge budgets vary across the full archive. The comparison does not isolate the causal effect of a particular harness design choice.
